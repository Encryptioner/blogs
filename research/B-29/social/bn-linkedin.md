# B-29 LinkedIn (বাংলা)

"Bun-এ চলে যাব কি?" - এটা আসলে একটা প্রশ্ন না, চারটা আলাদা সিদ্ধান্ত।

এখন কেন: Deno সদ্য Cloudflare-এ যোগ দিয়েছে — রানটাইমের হাতে আর এক বছরের মেইনটেন্যান্স, Deploy বন্ধ হচ্ছে। ইন্ডিপেন্ডেন্ট রানটাইম বলতে এখন টিকে আছে শুধু Node আর Bun।

দুইটা প্রোডাকশন মনোরেপো (Express + Mongoose API, Vue ক্লায়েন্ট, pnpm, Node 24) নিয়ে আমি Bun-এর সম্ভাব্যতা যাচাই করেছি। আসল রিপোতে হাত না দিয়ে কপি করে, প্রতিটা ধাপ আলাদাভাবে মেপে। লেখাটা শুরু হয়েছে জাভাস্ক্রিপ্ট রানটাইম আসলে কী দিয়ে — চারটা লেয়ার, আর যুদ্ধটা চলে ওপরের লেয়ারগুলোতে, ইঞ্জিনে না।

যা পেয়েছি:

- প্যাকেজ ম্যানেজার: কাজ করে। `bun install` pnpm লকফাইল পড়ে হুবহু একই প্যাকেজ রিজলভ করেছে। তবে warm pnpm store-এর চেয়ে দ্রুত হয়নি। ডিফল্ট isolated linker-এ Vue বিল্ড ভেঙে গিয়েছিল, hoisted linker দিয়ে ঠিক হয়েছে।
- স্ক্রিপ্ট রানার: বেশিরভাগ ঠিক আছে। শেয়ার্ড প্যাকেজ বিল্ড ৯.২ সেকেন্ড থেকে ৫.৬ সেকেন্ডে নেমেছে, vue-tsc প্রায় ২ থেকে ৪ গুণ দ্রুত চলেছে। তবে tsc-তে Bun runtime জোর করে দিলে উল্টো ধীর হয়েছে।
- সার্ভার রানটাইম: sharp, puppeteer, Mongoose, BullMQ, socket.io লোড হয়েছে। কিন্তু ডাটাবেস কানেকশন ফেইল করার প্রায় ৩০ সেকেন্ড পর অ্যাপ exit code 1 দিয়ে বন্ধ হয়ে গেছে, Node-এ হয়নি। কারণ বের করতে পারিনি, তাই এটা প্রোডাকশনে পাঠাতাম না।
- ক্লায়েন্ট বান্ডলার: Bun-এর নিচে Vue CLI ফেইল করেছে বা আটকে গেছে। Bun থাকুক বা না থাকুক, Vite-এ যাওয়া দরকার।

আমার সুপারিশ: Bun-কে ঐচ্ছিক প্যাকেজ ম্যানেজার ও স্ক্রিপ্ট লঞ্চার হিসেবে নিন, ক্লায়েন্ট Vite-এ সরান, আর সার্ভার রানটাইমে যাওয়ার আগে soak test করুন।
