Deck 10 · branchdiff features

Two new front doors.

A full-screen terminal picker for the people who live in the shell, and a VS Code extension that puts the whole UI in an editor tab — both driving the same local server you already trust.

branchdiff view Open VSX extension same server · same data localhost:5391
02 · the problem

The tool was local — but the doorways weren't where you were.

  • Terminal people juggled flags. Everything reachable — list, stats, history, auto cron — but each lives behind its own subcommand you had to remember.
  • Editor people context-switched. The review surface is a browser tab. Reviewing meant leaving the editor, not the repository.
  • Adoption friction, again. "I don't have Node" was solved with six package managers. "I don't want a second window" is the same itch, one layer up.
The pattern: every earlier itch was about the review. This one was about the doorway — and it had the same fix: meet people where they already are.
03 · branchdiff view

One full-screen picker for everything.

~/work — branchdiff view
❯ Stats Browse running instances Kill all New comparison Config Branches · History · Search Auto sessions · Cron Guideline · Changelog # j/k or ↑/↓ to move · digits to jump # r refresh · q quit · Esc back
  • Every surface, one menu. Stats, running instances, a new comparison, config, repo exploration, auto sessions, cron — no subcommand recall required.
  • Repo rows vs all-repo rows. Run inside a repo, you get that repo's entries; run from a parent directory, you get everything.
  • Kill from the picker. Browse running instances and stop any of them — no --port archaeology.
  • Honest outside a TTY. Piped or scripted, it prints the same plain listing branchdiff list would.
04 · what view maps to

Every menu entry is a deck you've already seen.

  • Browse running instances → Kill all — sessions and multi-instance targeting, deck 06.
  • Branches · History · Search — the repo exploration suite, deck 07.
  • Auto sessions · Cron — unattended review and its schedules, decks 05 and 08.
  • Stats — the usage dashboard, with its linkable sections and sticky jump bar, deck 06.
  • Config · Guideline · Changelog — everything else you'd otherwise open a browser for.
Nothing new to learn. The picker doesn't add capability — it removes the step where you had to remember which command owned the thing you wanted.
05 · the extension

The whole UI, inside the editor.

  • Full web UI in an editor tab. Not a summary panel — the same diff, comments, and lifecycle surface the browser gets, rendered in a tab that lives with your code.
  • Activity-bar panel. Live counts for running instances, auto sessions, and cron schedules, always visible in the sidebar.
  • Status-bar quick pick. One click from anywhere in the editor to open, copy a link, or jump to a session.
  • Copy link / Open in browser. Share the exact URL, or hand the tab to your browser when you want it there.
Why it matters: the review stops being a different place. Your diff, your comments, and your PR actions sit in the same window as the code they're about.
06 · zero-touch server

It adopts your server — or starts one. Zero config.

  • Reads the small registry file the CLI maintains for its running instances.
  • A healthy match means adopt — the extension attaches to the server you already have.
  • No match means spawn — it starts one, exactly as the CLI would.
  • No new trust surface: same server, same SQLite under ~/.branchdiff/, same everything.
The rule from deck 02 holds: local-first isn't a feature you trade away for convenience. The editor tab is a window onto the same localhost server — nothing new leaves the machine.
07 · getting it

One .vsix, every VS Code-family editor.

extensions panel
# inside VS Code, Cursor, or any Open VSX-fed editor: # search "branchdiff" → Install # or from the terminal, same package for every editor: $ code --install-extension branchdiff.vsix # .vsix straight from the GitHub releases page $ branchdiff view # the terminal front door needs no extension at all
Published on Open VSX — the registry the VS Code family draws from — with the identical .vsix on the releases page for manual installs. One package, every editor shape.
08 · recap

Same tool. Pick your window.

The terminal got a lobby and the editor got the whole house — both are thin front ends over the one local server everything else in this series already runs on.

  • branchdiff view — every surface in one full-screen picker; arrows or digits, no flags.
  • VS Code extension — full UI in a tab, activity-bar counts, status-bar quick pick, on Open VSX.
  • Zero-touch server: adopt if running, spawn if not — no new trust surface.
  • Non-TTY honesty: view piped prints the plain list output.
