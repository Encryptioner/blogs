Deck 09 · branchdiff features

Orientation, before a single token is spent.

Hand an AI a 40-file diff and it has to figure out what's actually connected before it can say anything useful. branchdiff computes that wiring locally and deterministically — zero AI tokens — and hands the reviewer a ready-made map before it starts.

change map zero AI tokens 3 files / 80 lines auto-threshold mermaid + ascii toolbar · PR description · auto
02 · the problem

The AI hits the wall of hunks, too.

  • Orientation is real work. A 40-file diff dropped on a reviewer — human or model — carries no map of what talks to what. Before it can say anything useful, it has to reconstruct the wiring by reading every file.
  • Not a new problem — a familiar one, on a new victim. "Fifty disconnected three-line hunk windows" is deck 01's native problem. Hand the same diff to an AI reviewer and it pays the identical tax, just silently, inside a prompt you can't see.
  • Tokens spent re-deriving structure aren't spent reviewing. Every paragraph the model uses to figure out "which files actually relate" is a paragraph it isn't using to catch a real bug.
  • A tangled diff and a big diff look the same from the outside. Nothing distinguishes "200 unrelated one-line changes" from "12 files that all depend on each other" until someone — or something — maps it.
The result: the first review pass on a large diff spends its earliest, most expensive reasoning on orientation the tool could have handed it for free.
03 · the solve

A map, computed locally — never an AI call.

branchdiff walks the diff's import graph on your machine — plain static analysis, not a model — and builds a change map: which areas moved, how they're wired, and whether the diff is one coherent change or several bundled together. It costs zero AI tokens, every time, because nothing in the computation is AI.

04 · what it answers

Six questions, answered before review starts.

  • Which areas moved, and by how much. Churn grouped by directory/module, not a flat file list.
  • Which areas are wired together. Import edges between the diff's own files — not the whole repo's graph.
  • One coherent change, or several bundled? Disconnected clusters read as separate concerns, not one story.
  • Which areas are brand-new. Files with no prior wiring into the rest of the diff.
  • How many review passes this session has already had. So the map itself carries nth-pass context.
  • A titled diagram per wired section. Rendered already — mermaid or ASCII, whichever the target platform supports.
Degrades gracefully. If wiring analysis can't run on a diff, the map falls back to the churn table alone — it never blocks a review over an incomplete graph.
05 · the wiring, in detail

Edges are labeled with the actual symbol, not "3 imports".

  • Not just an import count. When branchdiff can tell, an edge is labeled with the specific new symbol the diff added — the function or class the wiring is actually about.
  • Doc comments fold in. A wired-to node's box pulls in that symbol's own doc comment, when the diff added one — the reviewer sees intent, not just a name.
  • Missing docs are flagged, not hidden. A matched symbol with no doc comment is called out explicitly — a small, honest nudge, not a silent gap.
change map · auth area
┌─────────────────────┐ │ auth/session.ts │ └──────────┬───────────┘ │ wires validateSession() ▼ ┌─────────────────────┐ │ api/routes/login.ts │ │ "Handles POST /login,│ │ issues session" │ └──────────┬───────────┘ │ wires findByEmail() ▼ ┌─────────────────────┐ │ db/models/user.ts │ │ ⚠ no doc comment │ └─────────────────────┘
06 · leads the review

The AI's general comment opens with the map.

  • Intent summary first, diagram right after. Every review pass on a large diff posts a general comment that starts with a short intent line, then the pre-rendered diagram — before any findings.
  • Mermaid where it renders, ASCII where it doesn't. Mermaid on GitHub and in branchdiff's own comment view; ASCII on Bitbucket, which can't render it on its own PR page.
  • One diagram per wired section. A PR that spans unrelated areas gets one titled diagram per section, not one tangled graph trying to show everything.
  • --no-change-map skips it outright; --change-map-exclude <glob> narrows what feeds the graph.
Orientation before opinion. A reviewer — human or AI — reads "here's what's wired to what" before it reads a single finding. The comment argues its case with the map already on the table.
07 · view on demand

See the map — without spending a review pass.

  • Toolbar button opens a modal with the same orientation diagrams the AI would see — computed on demand.
  • Costs nothing until you click it. No AI call, no review pass — it's the same local computation, just surfaced directly.
  • Mermaid / Ascii toggle switches format from the one fetch already in hand — no re-computation.
  • Copy markdown copies whichever format is currently showing.
toolbar
# in the browser → toolbar "Change map" button → modal opens, diagrams computed on demand → Mermaid / Ascii toggle — same fetch → Copy markdown — whichever format is showing
08 · insert into a PR

One click, and it's in the PR description.

  • Insert row, in create-PR and edit-PR dialogs. A Change map button splices the block into the description as editable markdown.
  • Its own heading, cleanly closed. Lands under ### Change map, closed with a --- rule — never bleeds into hand-written description text.
  • Re-click updates it in place; a small × removes it.
  • Bitbucket gets images, not raw mermaid. Its PR page can't render mermaid on its own, so each diagram is rendered to an image and uploaded to the repo's Downloads area at save time — falling back to plain text for the whole map if any single upload fails.
PR description
## Summary …your own description text… ### Change map ```mermaid graph TD auth[auth/session.ts] --> login[api/routes/login.ts] login --> user[db/models/user.ts] ``` ---
09 · viewer polish

A mermaid diagram, viewed like a real diagram.

  • Titled frontmatter, sticky. A title: YAML frontmatter block becomes the sticky header of a "view full diagram" popup — you always know which section you're looking at.
  • Zoom in / out / reset. A dense wiring graph on a small PR-comment card stops being a squint test.
  • One-click SVG download. Pull the diagram out to paste into a design doc, a Slack thread, or a ticket — full fidelity, not a screenshot.
Same diagram, everywhere it can render. The popup is the same underlying mermaid the general comment posted — branchdiff's comment view just gives it real viewer controls instead of a static, uncontrollable embed.
10 · how to use it

Real commands — and it's on by default.

~/repo
# includes the change map automatically past the size threshold $ branchdiff agent diff # skip it outright $ branchdiff agent diff --no-change-map # narrow what feeds the graph $ branchdiff agent diff --change-map-exclude 'vendor/**' # the AI reviewer gets it automatically, every pass $ branchdiff auto --tool claude
  • In the browser: toolbar → Change map button → Mermaid / Ascii toggle → Copy markdown.
  • In a PR dialog: create or edit → Insert row → Change map button.
  • Same threshold everywhere — agent diff, review context, review run, and auto all trigger it past 3 files or 80 changed lines.
11 · honest boundary

Structural, not semantic.

  • It's an import graph, not a code review. It tells you what's connected — not whether the wiring is correct. Two files calling each other correctly and two files calling each other wrongly draw the exact same edge.
  • It doesn't shrink the diff's own complexity. A genuinely tangled 200-file diff still produces a genuinely complex map. The map doesn't make the diff simpler — it makes the complexity visible instead of hidden inside fifty separate files.
The honest framing: a change map is orientation, not judgment. It's the fastest way to see what a diff touches before you — or the AI — decide whether it touches it well.
12 · recap

Orientation the AI gets for free.

A change map is computed locally and deterministically — zero AI tokens, every time — once a diff crosses 3 files or 80 changed lines. It answers what moved, what's wired to what (with real symbols, not counts), whether the diff is coherent or bundled, and what's brand-new — then hands a ready-made diagram to whichever surface needs it: the AI's review comment, the browser toolbar, or the PR description itself.

  • Zero AI tokens — pure local static analysis, never a model call.
  • Auto-triggers past 3 files / 80 changed lines, in agent diff, review context, review run, and auto.
  • Edges labeled with actual new symbols; doc comments fold in; missing docs flagged.
  • Review comments lead with an intent summary + diagram — mermaid on GitHub, ASCII on Bitbucket.
  • View on demand from the toolbar; insert straight into a PR description, updatable in place.
  • Structural, not semantic — tells you what's connected, not whether it's correct.
