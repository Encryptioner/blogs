Deck 08 · branchdiff features

Every repo's open PRs, in one cycle.

Maintaining more than one repo used to mean cd in, run auto, wait, cd out, repeat — one decision fragmented across N terminals. Now one branchdiff auto run scans every repo, gathers their PRs into a single list, and reports what each pass reviewed.

--repo-paths name them, or discover them one combined list · GitHub + Bitbucket --keep-servers tidies up after every other flag works per-repo
02 · the problem

The per-repo loop — one decision, N terminals.

Today: auto one repo at a time

Reviewing open PRs across several repos means cd in, run, wait, cd out, repeat. Each run re-prompts and re-pays startup. The real question — "which of my open PRs need me right now?" — is split into one prompt per repo.

The shell-loop workaround breaks

for d in */; do (cd "$d" && branchdiff auto …); done cannot build one combined selection list — the requirement's central ask. It re-prompts per repo, silently breaks on non-repo directories, gives no cross-repo summary, and leaves an unbounded number of servers behind.

The cost: a side-projects/-shaped parent with ~25 repos and a handful of open PRs each is twenty-odd manual runs — or one shell loop that still can't show you all your candidates together.
03 · the solve

One auto run, every repo — same flags you already know.

Point auto at a set of repos. It scans each one, gathers every open PR — GitHub and Bitbucket — into a single candidate list, you pick once, and each selected PR is reviewed with the working directory switched into its own repo. Every existing flag behaves exactly as if auto had been launched from that repo.

~/side-projects
# name repos explicitly… $ branchdiff auto --repo-paths ~/work/api,~/work/web --skill # …or just run it from the parent directory $ branchdiff auto --tool claude # cwd isn't a repo → scans every direct child repo
Two ways in, one rule. --repo-paths names them; no flag and the current directory decides. The invocation cwd doesn't even have to be a git repo.
04 · discovery

Discovery is depth-1 — one consistent rule.

  • cwd is a repo → that repo. Today's behavior, byte-identical — children are not scanned.
  • cwd isn't a repo → its direct child repos. Depth 1 only — never a grandchild, no recursion.
  • --repo-paths <parent> means "every repo in there" — same depth-1 rule.
  • A non-repo path passed explicitly expands to its direct child repos; a nonexistent path is a hard error (exit 1), so a typo reviews nothing silently.
Sensible exclusions. Entries whose name starts with . (covers .git, .worktrees) and node_modules are never discovered. A .worktrees/pr-12 checkout retargets its main repo — never counted as a separate target.
05 · one list

One list, both forges, flat numbering.

  • GitHub and Bitbucket PRs from every repo land in one combined candidate list.
  • Grouped under repo headings, with flat global numbering — pick across the whole set at one prompt.
  • Ranges: 1-5 alongside a (all), 2,5, q (quit). Picking one repo's worth out of 60 stops being twelve typed numbers.
  • Colliding names disambiguated — two repos named api render as api (work/) vs api (oss/), stable for the whole run.
~/side-projects
Scanning 3 repos (4 at a time)… [1/3] api 2 open, 1 need review [2/3] web 3 open, 2 need review [3/3] worker 1 open, 1 need review -- api ----- 1 #142 feat: webhook retry (4 new) -- web ----- 2 #151 fix: race in queue (2 new) 3 #7 docs: API reference (1 new) -- worker -- 4 #9 chore: bump deps (3 new) Pick (a=all, 1-3, q=quit): 1-3
06 · consent

Discovered repos ask before the blast radius.

The riskier action never has the weaker gate. Running --auto-review --auto-push over a parent directory would otherwise publish AI comments to every open PR in every child repo with no prompt. So when the run will proceed without showing a list, and the targets were discovered rather than named, auto asks once — listing every repo it's about to touch.
  • Explicit --repo-paths never prompts — you typed the set.
  • An interactive run without --auto-review never prompts — the candidate list is already the consent step.
  • Non-interactive shell → refuses (exit 1), naming --repo-paths as the way to run unattended. --fresh over discovered repos shares the same guard.
  • Asked once per run, not per cycle — so a --watch loop doesn't block every five minutes.
07 · device-friendly

Scales to 25 repos without 25 subprocesses in flight.

--repo-concurrency
default 4 · clamp 1–16
Bounded worker pool for the scan phase.
sequential
repos, one at a time
--parallel still fans out PRs within a repo.
skip — no remote
local-only repos
No fetch, no PR query, no wasted subprocess.
  • Reads don't chdir. The scan threads an explicit working directory through every git/gh/Bitbucket call, so concurrent workers never race on a process-global cwd.
  • "No PRs" is distinguished from "could not ask." An unauthenticated host reports differently from a repo with zero open PRs — one run-level hint, not a warning per repo.
08 · keep-servers

--keep-servers tidies up after — not a peak cap.

  • Bounds how many servers the run leaves alive. Default: all for one repo, 4 for multi-repo. 0 leaves none.
  • One sweep, once per cycle, after every review is done — never mid-cycle, never per PR.
  • Only finished-review servers are retired. A mid-review server is never shut down, regardless of the cap.
  • Only servers this run spawned. A sibling auto, a hand-started server, a leftover — all left alone.
cycle end
3 repos · 4 reviewed · 0 failed · 1 skipped 6 servers spawned, 2 live, 4 retired (--keep-servers 2) reopen any session with: branchdiff <pr-url>
Residual, not peak. The cap bounds what a cycle leaves behind, not what's alive during it — that peak is set by --parallel and how many PRs you select. Ctrl-C skips the sweep entirely; clean up leftover servers with branchdiff killall.
09 · resilience

Kill a server mid-run — no crash, no false "reviewed".

The hazard: you can run branchdiff kill --port N or killall at any point while auto is running. Worse, an agentic CLI catches its own tool errors and exits 0 — so a review whose comments never landed could look like success.
The guarantee: every variant is handled — killed mid-review, between review and push, after completion, or killall wiping every session. After the AI child returns, auto probes the pinned session; a dead one is a review failure regardless of the child's exit code. A PR is stamped reviewed only once its findings actually publish — so the next cycle offers it again, no --no-skip needed.
  • One health probe per PR pass — no polling loop, no background health checker left running.
  • A genuinely clean review (0 comments) still passes — "nothing to say" is never turned into a failure.
10 · cycle report

Every cycle ends with what it did, and where.

The per-PR lines print while servers are still live and before later PRs run — by cycle end their URLs may be stale. The report is the one place state is settled: each PR's outcome, its remote URL, and its local session URL marked live or stopped, grouped by repo with the repo's path.

cycle report
3 repos · 4 reviewed · 0 failed · 1 skipped api (~/work/api) #142 done · 3 comments ● running → github.com/org/repo/pull/142 → localhost:5391 web (~/work/web) #151 done · 2 comments ○ stopped #7 ready ○ stopped reopen any: branchdiff <pr-url>
Exit codes you can script. 0 clean (or a deliberate quit); 1 usage/config refusal — nothing attempted; 2 the run proceeded but something was skipped or failed. A run whose only non-zero counter is skipped still exits 0.
11 · how to use it

Real commands — everything from deck 05 still applies.

~/side-projects
# review every repo under the cwd, skill + resolve, tidy up $ branchdiff auto \ --repo-paths ~/work \ --skill --auto-resolve --worktree \ --keep-servers 2 # watch all repos, loop every 10 min $ branchdiff auto --watch 10 --notify # bound the scan, keep no servers $ branchdiff auto --repo-concurrency 8 --keep-servers 0
  • --source / --dest / --skip-author filter within every repo; --auto-approve / --auto-request-changes gate per PR.
  • Repo-local CLAUDE.md / AGENTS.md are picked up per repo — the AI child runs with cwd set to that repo.
  • --watch re-resolves targets each cycle: a repo cloned into the parent mid-watch is picked up without a restart.
12 · recap

One cycle, every repo — same control you already trust.

branchdiff auto now spans a set of repos in one run: discover or name them, pick from one combined list across both forges, and get a cross-repo report. Every escalation flag from deck 05 still applies — per repo.

  • --repo-paths or depth-1 discovery; one list, GitHub + Bitbucket, flat numbering with 1-5 ranges.
  • Discovered repos ask before the blast radius; non-interactive refuses.
  • --repo-concurrency bounds the scan; --keep-servers tidies up after (residual, not peak).
  • Kill-friendly: no false "reviewed" — a PR is stamped only once its findings publish.
